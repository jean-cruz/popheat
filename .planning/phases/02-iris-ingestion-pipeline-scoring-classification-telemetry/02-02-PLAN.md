<objective>
Turn Plan 02-01's one-venue tracer into the real, spec-complete ingestion pipeline: real
150-venue batches every 3 seconds, full-catalog circular cycling with correct wrap-around,
per-batch failure isolation so one bad batch never stops the next scheduled tick,
config-file-driven heat thresholds re-read every cycle (no redeploy), and hardened,
non-blocking, recent-20-batches telemetry. Extracts the pure popularity/classification/
throughput math out of `components.py` into a standalone, IRIS-independent `scoring.py` module
with real unit tests -- the math itself does not change, only where it lives and how it is
tested and configured.

Purpose: Plan 02-01 proved the architecture end-to-end for one venue; this plan makes the
pipeline actually satisfy the phase's batching, cycling, resilience, and telemetry
requirements so it can run unattended for the length of a live contest demo.
Output: a continuously-cycling, failure-isolated, config-driven, telemetry-complete production
running against the full 906-venue catalog, backed by a tested pure-Python scoring module.
</objective>
