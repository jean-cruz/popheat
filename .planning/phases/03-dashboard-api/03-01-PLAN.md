<objective>
Stand up the read-only REST layer over Phase 2's persisted data and the thinnest possible
end-to-end dashboard path: one venue, fetched from a live IRIS `%CSP.REST` class, rendered as a
marker on a Leaflet map served as a static IRIS CSP page from the same container. Then expand the
REST class with the remaining three data endpoints (counts, telemetry, status) that Plans 03-02
and 03-03 will consume.

Purpose: prove the whole vertical slice — public HTTP → REST dispatch → embedded SQL against
Phase 2's `PopHeat.Reading`/`PopHeat.BatchTelemetry` tables → JSON → browser render — works before
any visual polish is added, and give Plans 03-02/03-03 a stable, fully-specified API contract to
build against.

Output: `PopHeat.API` (REST dispatch class, 4 routes), `PopHeat.Reading`'s new `LatestPerVenue`/
`CountsByHeatLevel` queries, a minimal `dashboard.csp`, and the web-application registration that
exposes both under the existing POPHEAT container/namespace.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet -> PopHeat.API (%CSP.REST) | Untrusted client GET requests reach /csp/popheat/api/{venues,counts,telemetry,status}; unauthenticated by design (D-06) |
| Public internet -> dashboard.csp (static CSP page) | Untrusted clients load and execute the page's HTML/JS in their own browser |
| PopHeat.API -> PopHeat.Reading / PopHeat.BatchTelemetry | Read-only embedded SQL queries against Phase 2's persisted data; the API never writes |
| dashboard.csp -> CDN (e.g. unpkg.com) | The browser loads Leaflet/Leaflet.heat JS/CSS from a third-party CDN at runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-03-01 | Tampering | PopHeat.API GET routes | high | mitigate | All four routes accept zero user-supplied query/path parameters; every SQL statement is a fixed, parameterless %SQLQuery/embedded-SQL string with no request input concatenated into it, closing off SQL injection entirely rather than relying on parameter binding |
| T-03-02 | Information Disclosure | PopHeat.API Status() method | medium | mitigate | Ens.Director.IsProductionRunning is called inside its own Try/Catch; any exception is caught and degrades the response to {"running": false} rather than surfacing an IRIS %Status error string or stack trace to the public client |
| T-03-03 | Denial of Service | PopHeat.API (all routes), unauthenticated + unrate-limited | low | accept | Single-container demo deployment for a judged contest window, not a multi-tenant production service; every query runs against already-indexed columns (VenueIdx, ObservedAtIdx) or RecentBatches()'s existing TOP-20 cap, so repeated requests stay cheap; rate limiting is out of scope for the one-day timeline and does not affect the deliverable's correctness |
| T-03-04 | Elevation of Privilege | /csp/popheat/api and /csp/popheat (both AutheEnabled=64, unauthenticated) | low | accept | Deliberate per D-06/UI-SPEC: the dashboard is public, read-only, no PII, no write operations, no secrets — matches the explicit contest-demo requirement for a login-free public view |
| T-03-05 | Tampering | PopHeat.API SQL statements against PopHeat.Reading/BatchTelemetry | high | mitigate | Every REST classmethod issues SELECT-only SQL; no INSERT/UPDATE/DELETE keyword appears anywhere in PopHeat.API.cls, preserving Phase 2's insert-only discipline from the read side |
| T-03-06 | Tampering | dashboard.csp's CDN-loaded Leaflet/Leaflet.heat script/link tags | medium | mitigate | Subresource Integrity (integrity= plus crossorigin="anonymous") attributes pin the expected hash on every CDN script/link tag, so a compromised or MITM'd CDN response is rejected by the browser instead of executing |

</threat_model>
