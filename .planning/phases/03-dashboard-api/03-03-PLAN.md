<objective>
Turn the dashboard from a one-shot render into the live, auto-refreshing view DASH-07 requires:
a 10-second polling loop that re-fetches and re-renders everything, a visible error state on fetch
failure that never silently hides stale data, and the remaining empty/loading edge states from
03-UI-SPEC.md.

Purpose: this is the requirement that makes the dashboard "live" rather than a static snapshot —
without it, the product does not meet its own name.

Output: `iris/PopHeat/www/dashboard.csp` extended with the refresh loop, in-flight concurrency
guard, stale-data banner, and empty state.
</objective>

  <action>
  Define `const REFRESH_INTERVAL_MS = 10000;` (exactly 10 seconds per D-08 — literal per the spec, not derived from Phase 2's 3-second ingestion cadence) and a module-level `let isRefreshing = false;` flag near the existing constants.

  Implement `async function refreshAll()`: if `isRefreshing` is already true, return immediately (the in-flight guard — a slow cycle never overlaps with the next scheduled one). Otherwise set `isRefreshing = true`, then in a try/finally block run the four fetches — `fetch(API_BASE + '/venues')`, `/counts`, `/telemetry`, `/status` — each awaited independently (not `Promise.all` with a single shared catch, so one endpoint's failure does not prevent the other three from rendering their own data). For each individual fetch: on success, parse the JSON and call that data type's existing renderer (renderHeatLayer + renderMarkers for /venues, renderCounts for /counts, renderTelemetry for /telemetry, renderStatus for /status — all four already exist from Plans 03-01/03-02); on failure (network error or a non-ok response per Plan 03-01's 500-on-genuine-error convention), call a new `recordFetchFailure()` helper instead of touching that region's DOM, leaving whatever was rendered previously untouched. In the `finally` block, set `isRefreshing = false`.

  Track a module-level `let lastSuccessfulFetchAt = null;` timestamp, updated to `new Date()` whenever ALL FOUR of the current cycle's fetches succeeded (not on a per-endpoint basis — this timestamp backs the D-07 banner copy).

  Wire the initial page load to call `refreshAll()` once immediately on `DOMContentLoaded`, then `setInterval(refreshAll, REFRESH_INTERVAL_MS)` to repeat it every 10 seconds — no full page reload, no `location.reload()` anywhere in the file.

  Implement the empty state: when the /venues response successfully parses to an empty array, show the "No readings yet" heading and its documented body copy (from 03-UI-SPEC.md's Copywriting Contract) in place of the map's data layers, while the base OSM tiles keep rendering underneath (do not call renderHeatLayer/renderMarkers with an empty array in a way that would visually differ from "no error" — treat empty-but-successful as its own explicit state, not a fallthrough of the error path).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet -> PopHeat.API (%CSP.REST) | Untrusted client GET requests reach /csp/popheat/api/{venues,counts,telemetry,status}; unauthenticated by design (D-06) |
| Public internet -> dashboard.csp (static CSP page) | Untrusted clients load and execute the page's HTML/JS in their own browser |
| PopHeat.API -> PopHeat.Reading / PopHeat.BatchTelemetry | Read-only embedded SQL queries against Phase 2's persisted data; the API never writes |
