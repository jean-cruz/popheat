> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — static HTML + vanilla JS, no build toolchain (locked by 03-CONTEXT.md D-05); shadcn requires a package-manager-driven build and does not apply to a zero-toolchain single-page deliverable |
| Preset | not applicable |
| Component library | none — hand-written HTML/CSS/JS, Leaflet.js loaded from CDN (D-01) for the map only |
| Icon library | none — zero-dependency bias (03-CONTEXT.md "Specific Ideas"); status indicator is a CSS-drawn dot, banner dismiss is a plain "×" character, map markers use Leaflet's built-in `circleMarker` primitive (no marker-icon asset needed) |
| Font | System font stack: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` — no webfont load, avoids an extra CDN dependency and FOUT risk during the live judged demo |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between status dot and its label text; gap between banner "×" and its text |
| sm | 8px | Gap between rows in the counts panel; gap between telemetry panel lines |
| md | 16px | Marker popup internal padding; banner vertical padding; default element spacing |
| lg | 24px | Floating panel internal padding; floating panel offset from map edge; banner horizontal padding |
| xl | 32px | Gap between the counts panel and the telemetry panel when both float in the same corner region |
| 2xl | 48px | unused this phase (reserved) |
| 3xl | 64px | unused this phase (reserved) |

Layout dimensions (not spacing tokens, but declared for consistency): top bar height is a fixed **56px** (holds "PopHeat" title left-aligned + status badge right-aligned); the map fills the remaining viewport (`100vh - 56px`), full-bleed, no padding.

Exceptions:
- Marker radii (CRITICO 14px, ALTO 10px — see Color/Interaction notes below) are map-primitive sizing, not spacing, and are exempt from the 8-point scale.
- Touch targets (banner dismiss button, marker tap area) are a minimum 44×44px hit area even where the visible glyph is smaller, for demo-day use on a tablet/phone.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 13px | 600 | 1.2 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Usage notes:
- **Display (28px/600)** is reserved for the four heat-level count numbers in the counts panel (e.g. the digit shown next to "CRITICO") — these are the numbers a judge should be able to read from across a room.
- **Heading (20px/600)** is the "PopHeat" top-bar title only.
- **Label (13px/600)** is used for the heat-level name next to each count, the status badge text, and telemetry panel field labels (e.g. "Throughput", "Last batch").
- **Body (16px/400)** is used for marker popup content and the stale-data banner message.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F5F6F8` (near-white neutral) | Page background beneath/around the map viewport; the OSM map tiles themselves supply the visually dominant surface once loaded |
| Secondary (30%) | `#1F2933` (dark slate) | Top bar background, floating counts panel background, floating telemetry panel background — all rendered as dark chrome so they read as UI, not map data |
| Accent (10%) | `#3B82F6` (blue) | Reserved for: the "Pipeline: Running" status-dot fill, the banner dismiss "×" hover/focus state, and marker popup "as of {time}" link-style timestamp text. Never used for heat-level meaning — kept deliberately distinct from the green/yellow/orange/red heat gradient so viewers never confuse app chrome with data |
| Destructive/Error | `#DC2626` (red) | Reserved for: the stale-data banner background/icon only (D-07). Not reused elsewhere so it never competes visually with the CRITICO heat-level red used on the map |

Heat gradient (locked by 03-CONTEXT.md D-02 — not re-opened, pinned to concrete values here since exact hex was left to this pass):

| Heat Level | Color | Hex |
|---|---|---|
| BAIXO | Green | `#2ECC71` |
| MEDIO | Yellow | `#F1C40F` |
| ALTO | Orange | `#E67E22` |
| CRITICO | Red | `#E74C3C` |

These four are the only colors used to encode heat-level meaning anywhere in the UI (map heat layer, individual markers, counts-panel chips, popup heat-level badge) — never reused for chrome, buttons, or status.

Accent reserved for: pipeline-running status dot, banner dismiss control interaction state, popup timestamp text. Never for heat-level encoding, never for "all interactive elements."

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Not applicable — this is a read-only, no-login dashboard with no form submission or primary action. The closest interactive affordances are "click a marker to view its popup" and "dismiss" on the stale-data banner (below) |
| Empty state heading | "No readings yet" |
| Empty state body | "The ingestion pipeline hasn't completed its first batch. This page will update automatically within a few seconds — no action needed." (shown when `/api/venues` returns zero rows, e.g. immediately after a fresh container start before Phase 2's first 3-second batch completes) |
| Error state | "Unable to refresh — showing last known data as of {last successful fetch time}." — locked verbatim by 03-CONTEXT.md D-07. Rendered as a dismissible banner directly under the top bar; last-known map/counts/telemetry data stays visible and unchanged underneath |
| Destructive confirmation | Not applicable — no destructive actions exist in this read-only dashboard (no delete, no write, no auth) |
| Status badge (running) | "Pipeline: Running" with filled accent-blue dot |
| Status badge (stopped) | "Pipeline: Stopped" with hollow gray dot — text label is always shown alongside the dot; color is never the sole signal (accessibility, and to avoid any ambiguity with heat-level colors) |
| Marker popup | "{Venue Name}" (bold, Body) / "{Category} · {HeatLevel}" (Label, colored per heat gradient) / "Popularity: {score}" / "as of {ObservedAt local time}" (accent-colored per above) |
| Counts panel | Four rows: "{count} BAIXO" / "{count} MEDIO" / "{count} ALTO" / "{count} CRITICO", count in Display size, label in Label size, each row's count digit colored per that level's heat color |
| Telemetry panel | "Last batch: {ReadingCount} readings · {ElapsedSeconds}s · {Throughput}/s" and "Recorded {RecordedAt local time}" — sourced from `PopHeat.BatchTelemetry.RecentBatches()` most-recent row |

## UI Considerations

Applicable state considerations resolved: 6 covered, 3 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | venues/counts on first load | ✅ covered | "No readings yet" empty state (see Copywriting Contract) shown when the venues endpoint returns zero rows; map still renders (tiles only, no data layer) rather than erroring |
| loading | initial page load before first successful fetch | 🧪 backstop | Counts panel shows "Loading live data…" placeholder text (Label size) in place of the four count rows until the first fetch resolves; map tiles load independently via Leaflet and are unaffected |
| error | any 10s refresh cycle fails | ✅ covered | D-07 banner, exact copy above, dismissible, last-known data stays visible and unchanged (locked decision, not re-opened here) |
| populated | normal mixed-heat-level state | ✅ covered | Heat layer renders every venue with min-weight applied (DASH-02, see below); ALTO/CRITICO get individually sized circleMarkers (DASH-03/04) |
| zero-one-many | zero venues currently ALTO or CRITICO | ✅ covered | Map shows the heat layer only, no individual markers rendered, counts panel correctly shows 0 for those rows — this is an expected normal state, not an error or empty state |
| zero-one-many | pipeline status endpoint unreachable independent of data fetch | 🧪 backstop | Status badge falls back to "Pipeline: Stopped" (hollow gray dot) rather than blank/crashing if the `IsProductionRunning` check itself errors — status is informational only (D-06) and never gates the rest of the page |
| overflow | many CRITICO/ALTO markers clustering in a small area | 🧪 backstop | Markers render at fixed radius with no clustering library (out of scope for the one-day build); visual overlap is acceptable, click still opens the correct popup for the topmost marker |
| long-text | long venue name in marker popup | ✅ covered | Popup content area has `max-width: 240px` and wraps text normally (no ellipsis truncation) — popups grow vertically to fit |
| partial | pipeline stopped but readings still displayed | ✅ covered | Status badge shows "Pipeline: Stopped" while venue/heat/counts/telemetry continue showing last-persisted data unchanged, per D-06's non-gating rule |

Pinned defaults (Claude's discretion per 03-CONTEXT.md, resolved here so the executor has concrete numbers):
- **Minimum visible heat weight (DASH-02):** heat-layer point weight = `max(popularity, 0.15)` on a 0–1 intensity scale, so even a 0.02-popularity venue stays visibly present on the heat layer rather than disappearing.
- **Marker sizing (DASH-04):** CRITICO marker radius = 14px; ALTO marker radius = 10px (both rendered as Leaflet `circleMarker`, filled with the matching heat-gradient color, white 1px stroke for contrast against varying tile backgrounds).
- **Heat layer implementation assumption:** a Leaflet heat-layer plugin loaded from CDN (e.g. Leaflet.heat) alongside core Leaflet — consistent with D-01's "no API key, no paid provider" CDN-only approach; radius/blur left to the executor's plugin defaults unless they visibly clash with the marker layer.
