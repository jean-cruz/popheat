    - Two venues with an identical `name` and `lat`/`lon` that round to the same 5-decimal value

    - Two venues with the same rounded coordinates but names differing only in case (`"Café Aroma"`
      vs `"café aroma"`) are NOT treated as duplicates — both are kept.
    - When two candidates collide, the surviving entry's `id` is the FIRST candidate's id, never the
      second's.
    - Feeding 3 venues where index 0 and index 2 are duplicates of each other (index 1 distinct)

## Trust Boundaries

Inherits the trust boundaries established in Plan 01-01 (Internet -> build_catalog.py,
build_catalog.py -> local filesystem, config -> build_catalog.py). This plan adds no new I/O and no
new trust boundary: `dedupe_venues` and `round5` are pure in-memory transforms over already-mapped,
already-whitelisted venue dicts, and `run()` is a refactor of existing orchestration, not a new
external surface.
